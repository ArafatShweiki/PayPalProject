# Dream Piggy Bank technical audit � 2026-10-26

## Outcome and scope

The existing React 19 / TypeScript / Vite UI and Express API were inspected, exercised, and repaired. Auth0 remains the login provider; the email and `paypal-sandbox` SDK flows remain intact. No Google login, replacement authentication, redesign, real payment, live profile creation, or destructive migration was introduced.

**Local verification succeeds. Hosted deployment is not ready.** The configured Supabase HTTP endpoint is reachable, but GET requests with the backend secret return HTTP 404 / `PGRST205` for every Dream Piggy Bank table, including `profiles.wallet_preferences`. The service-role OpenAPI response exposes none of the Dream Piggy Bank RPCs. This establishes that the expected schema is unavailable through this project's Data API; SQL Editor diagnostics are needed to distinguish unapplied migrations, wrong project, and grants/schema-cache configuration. `SUPABASE_ENABLED` remains `false` in the user's local configuration. No local credential values or live records were printed.

An initial SDK HEAD probe incorrectly appeared successful. It was cross-checked against OpenAPI and GET responses, corrected, and is **not** counted as evidence that hosted tables exist. Anonymous 404 responses against missing/inaccessible tables do **not** prove RLS works.

## Environment and deployment

Runtime precedence is process/deployment environment, `.env.local`, `.env`, then `.env.auth0`. Tests skip local files; E2E opts out explicitly. Only public Auth0 identifiers and Supabase URL/publishable key are delivered through `/api/config`. No `VITE_` secret variables are used. The backend secret stays in server modules.

Current local flags are Auth0 enabled, Supabase disabled, demo disabled and SQLite storage. Supabase URL/new publishable/new secret keys are populated. Gemini, merchant PayPal, Firestore service account and cron secret are absent. Do not turn Supabase on until schema and Auth0 third-party configuration are ready.

The Vercel entry point and Vite output/rewrites fit the existing Express-plus-SPA architecture. Node 24 is a [supported Vercel runtime](https://vercel.com/docs/functions/runtimes/node-js/node-js-versions). However, this hybrid app still needs `STORAGE=firestore` and a server-only `FIREBASE_SERVICE_ACCOUNT` for auxiliary records and rate history; Supabase financial tables do not remove that dependency. Vercel's [function filesystem is not durable application storage](https://vercel.com/docs/functions/runtimes). The server intentionally refuses a Vercel deployment with local SQLite. Set the real production `APP_ORIGIN`, Auth0 URLs and `CRON_SECRET` before deployment. No remote Vercel deployment was attempted.
